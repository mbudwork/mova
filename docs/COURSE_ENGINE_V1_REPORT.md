# COURSE ENGINE V1 — REPORT

Реализовано поверх находок предыдущего pre-launch аудита. Ничего в
ElevenLabs/Stripe/дизайне/gamification не тронуто — это прямо запрещённая
зона задачи.

---

## BEFORE → что было сломано

Три независимых, подтверждённых кодом дефекта:

1. **`getLesson()` игнорировал `role`.** Запрос забирал все строки
   `lesson_phrases` урока — и `primary`, и `review_pool` — без фильтра,
   сортируя вперемешку по `order_index`, который не уникален между ролями.
   На практике урок L02 показывал **20 фраз вместо 10**, без каких-либо
   пометок, что новое, а что нет.
2. **Retrieval practice не существовал.** `LessonPlayer` — режим «показать
   перевод → дальше», ни одного вопроса с ответом. `phrase_progress`
   засевался один раз при `complete_lesson()` и никогда не обновлялся.
3. **`/app/review` — статичная заглушка.** Не делала ни одного запроса к
   БД, всегда показывала «нечего повторять».

## AFTER → как теперь работает

**Механика:** AUDIO (пока честный текстовый режим, см. ниже) → 3–4 варианта
значения → ответ → ✓/✕ → немецкий + перевод → дальше. Немецкий текст
физически не появляется в разметке до ответа — та же структурная гарантия
(`shouldRevealGerman`), что уже стояла в бесплатном тесте, теперь защищает и
платный курс.

**Состояния** — монотонная лестница `WEAK(0) < LEARNING(1) < UNDERSTOOD(2) <
MASTERED(3)`. Верно → на ступень выше (потолок MASTERED). Неверно → сброс в
WEAK из любого состояния. Реализовано как SQL-функция
`next_progress_state()`, проверено 10 явными тестами на каждый переход.

**Интервалы** (фиксированные, без экспоненциальной сложности):

| Состояние после ответа | Следующий показ |
|---|---|
| WEAK | 4 часа |
| LEARNING | 1 день |
| UNDERSTOOD | 3 дня |
| MASTERED | 14 дней |

**Запись прогресса** — `record_answer(phrase_id, correct)`, единственный
писатель `phrase_progress`, вызывается один раз на каждый реальный ответ, а
не пачкой при завершении урока. Проверяет видимость фразы (approved,
безопасность, entitlement) заново — тот же контур, что и `phrases_read`
RLS-политика.

**Урок** — только `role='primary'`, 8–10 фраз, фильтрация вынесена в
TypeScript (не в PostgREST embedded-filter), потому что это поведение никогда
не проверялось против живого PostgREST — а против прямого SQL проверено и
детерминировано.

**Review** — `/app/review` реальный: `due_review_phrases()` отдаёть WEAK
(приоритетно) + просроченные по времени, до 10 фраз за сессию, та же
механика упражнения, что в уроке.

**Дистракторы** — без новой таблицы. Реальные переводы других фраз того же
урока (в уроке) или того же батча повторения (в review). Дедуплицируются по
тексту перевода, деградируют до 2–3 вариантов вместо дублирования, если пул
маленький — проверено 10 unit-тестами на `buildOptions()`.

**Честная деградация без аудио.** Аудио физически не существует (0/564).
Упражнение показывает видимую плашку «аудио ещё не записано — сейчас это
упражнение на чтение, не на слух» и раскрывает немецкий текст сразу, вместо
звука. Это не замаскированный обман — баннер виден всегда, и это единственный
способ, которым движок вообще можно было протестировать сейчас. Ответы,
записанные в этом режиме, тестируют чтение, а не слух; когда появится аудио,
существующий прогресс не сбрасывается — решение осознанное, отмечено ниже как
открытый вопрос.

## DB — что реально используется

**Новое:**
- `phrase_progress.last_answer_correct` (добавлена колонка)
- `next_progress_state(state, correct)` — чистая функция состояния
- `next_review_interval(state)` — чистая функция интервала
- `record_answer(phrase_id, correct)` — единственный писатель прогресса
- `due_review_phrases(limit)` — источник данных для review

**Изменено:**
- `complete_lesson()` — больше не трогает `phrase_progress`, только
  `lesson_progress`. Идемпотентность сохранена и перепроверена.
- `course_progress()` — `phrases_total` теперь считает **только
  distinct primary** (164 фразы), а не все строки `lesson_phrases` (295).

**Оставлено нетронутым:** `phrase_progress.correct_count`,
`incorrect_count`, `current_streak`, `next_review_at`, `state` — вся схема
из PHASE 1 подошла без изменений, кроме одной добавленной колонки. Дублирующей
системы не создавалось.

## TESTS — какие реальные user journeys проверены

167 интеграционных тестов (было 134, добавлено 33 в
`course-engine-v2.test.ts`), включая явную регрессию трёх старых тестов,
писавшихся под прежнее (ошибочное) поведение `complete_lesson()`.

Из списка сценариев задачи — проверено:

| Сценарий | Тест |
|---|---|
| Правильный ответ | `record_answer` — correct → LEARNING, интервал ~24ч |
| Неправильный ответ | `record_answer` — incorrect → WEAK, интервал ~4ч |
| Повторный ответ (другая сессия) | вся лестница WEAK→LEARNING→UNDERSTOOD→MASTERED→WEAK→LEARNING, 5 последовательных тестов |
| Double-click | два быстрых вызова на одну фразу — состояние не портится, счётчик корректно накапливается |
| Reload | новая транзакция читает то же состояние |
| Другой девайс | две независимые сессии видят идентичные данные |
| Lesson completion | завершение не сеет прогресс пачкой; отвеченные — есть, неотвеченные — нет |
| Due review | WEAK показывается немедленно вне очереди по времени; не-WEAK не готовое — не показывается; сортировка WEAK впереди просроченных; лимит батча соблюдается |
| Weak → Understood → Mastered | покрыто лестницей состояний |
| Mastered → ошибка | явный тест демоушна в WEAK, не в промежуточное состояние |
| Отсутствие due-фраз | пустой результат для свежего пользователя |
| Изоляция между пользователями | чужой прогресс не виден и не изменяем |
| Попытка ответить на недоступную фразу | `draft`-фраза корректно отклоняется `record_answer` |

**Не проверено:** «закрытие браузера» и «возвращение завтра» в буквальном
смысле — эквивалентно проверены как «новая транзакция/сессия читает
сохранённое состояние» и «просроченный по времени next_review_at
показывается снова», поскольку у меня нет реального браузера и течения
времени. E2E в Playwright по-прежнему не запускается — окружение не
устанавливает браузер, шестая фаза подряд. Против живого
Supabase/PostgREST — не проверялось, как и раньше.

## CONTENT — что сделано с primary/review/orphans

**Ничего не удалено и не переклассифицировано молча.** Перед изменением кода
проверил, что даст автоматическое продвижение orphan-фраз в `primary`:

- 13 из 16 «целевых» уроков **удвоили бы** свой primary-набор (10→20),
  потому что первое появление orphan-фразы почти всегда приходится на урок, у
  которого уже есть полный комплект из 10 primary. Это воспроизвело бы тот же
  баг под другим именем.
- Только 3 урока (L03/L04/L06) получили бы мягкий прирост (+2/+3/+4).

**Решение: не продвигать ничего автоматически.** Код теперь читает только
`role='primary'` — это одно исправление уже устраняет 100% случаев удвоения
урока, используя исключительно уже корректно размеченные данные (425 строк
`primary`, 164 уникальные фразы).

**135 «зависших» фраз** (review_pool, никогда не primary) остаются в БД
нетронутыми, физически недостижимыми через уроки сейчас. Распределены
примерно поровну по модулям контента (7–10 на модуль — Workday, Safety,
ELEKTRO, MAURER и др.), что похоже не на случайный мусор, а на **полноценный
второй набор контента на модуль**, который так и не получил своего места в
последовательности уроков. Решение, что с ним делать — новые отдельные уроки,
альтернативный трек для продвинутых, или на слом — это контентная стратегия,
не то, что я вправе решить сам.

7 строк review, физически стоящих раньше своего единственного primary-появления
(временной парадокс из первого аудита) — стали неактуальны: `review_pool`
больше не читается приложением вообще, так что этот дефект данных больше не
может создать пользовательский баг, но сами строки не тронуты.

## ПРАВКА — spaced repetition timing (после вашей проверки)

Найдены и исправлены два реальных бага в первой версии движка. Оба — в
временной логике, не в архитектуре: сама лестница состояний и таблица
интервалов не менялись.

### 1. `due_review_phrases()` обходил собственный интервал WEAK

Было: `next_review_at <= now() OR state = 'weak'` — любая ошибочная фраза
попадала в review немедленно, вне зависимости от 4-часового интервала.

Стало: `next_review_at <= now()` — единственный фильтр. WEAK получает
приоритет **в сортировке** среди уже наступивших фраз, но не обходит
собственное время ожидания.

### 2. `record_answer()` повышал mastery на любом правильном ответе

Было: три быстрых правильных ответа подряд на одну фразу поднимали её до
MASTERED за секунды — spaced repetition не имел смысла.

Стало — разделены два пути:

- **Первый показ фразы** (строки `phrase_progress` ещё нет) — единственный
  случай, применяющийся безусловно: верно → LEARNING, неверно → WEAK.
- **Плановое повторение** (`now() >= next_review_at`) — здесь и только здесь
  правильный ответ двигает лестницу дальше.
- **Досрочный повтор** (`now() < next_review_at`, правильный ответ) —
  засчитывается как тренировка: `correct_count` растёт, но `state` и
  `next_review_at` не меняются. Нельзя фармить прогресс, открывая старый урок
  повторно.
- **Ошибка — всегда сигнал**, в любой момент: безусловно переводит в WEAK и
  сбрасывает часы на 4 часа заново, даже если это был досрочный повтор.

### Тесты

172/172 (было 167 → +5 к сумме, поскольку три старых теста, кодировавших
прежнее, неверное поведение, переписаны, а не просто добавлены сверху).
Из требуемого списка:

| Сценарий | Тест |
|---|---|
| WEAK не появляется до +4ч | `does NOT surface a WEAK phrase before its own 4-hour interval` |
| WEAK появляется после +4ч | `DOES surface a WEAK phrase once its 4-hour interval has elapsed` |
| LEARNING не повышается повторным ответом через минуту | `a second correct answer BEFORE next_review_at does not promote` |
| LEARNING повышается в scheduled review | `once next_review_at has genuinely elapsed, a correct answer promotes LEARNING → UNDERSTOOD` |
| UNDERSTOOD аналогично | `a correct answer before the NEW next_review_at again does not promote past UNDERSTOOD` + `once due again... UNDERSTOOD → MASTERED` |
| 3 быстрых верных ответа НЕ дают MASTERED | `three rapid correct answers never reach MASTERED` — итог: LEARNING, не выше |
| MASTERED только через реальные review-стадии | вся лестница теперь продвигается только через искусственно состаренный `next_review_at` (`makeDue()`), не последовательными вызовами |
| Повторное прохождение завершённого урока не фармит | `replaying a completed lesson cannot farm progress` — 10 фраз урока пройдены дважды подряд, состояние и расписание идентичны до и после |

Полная регрессия: 172/172, typecheck 0 ошибок, RLS не пробит, build успешен.
